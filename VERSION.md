## Versioning Philosophy

Neowtwork uses semantic versioning: `MAJOR.MINOR.PATCH`.

- `PATCH` versions are for bug fixes, polish, documentation updates, and small tweaks.
- `MINOR` versions are for new user-facing features or meaningful feature expansions.
- `MAJOR` versions are for major architectural changes or product milestones.

Version numbers should describe the project state in plain English, not create ceremony. Keep the version useful for understanding progress, sharing checkpoints, and explaining what changed.

## Developer Notes

Every meaningful `DEVLOG.md` entry should include:

- version number
- feature summary
- commit hash
- verification status
